# Вхід в адмінку — Telegram Login, доступ = членство в чаті «Фінанси»

В адмінку входять через Telegram Login Widget бота магазину, а доступ дає поточне членство в окремому чаті «Фінанси» (`getChatMember`). Воно перевіряється заново при кожному оновленні сесії, тож людина, яку прибрали з чату, втрачає доступ без деплою. Членство в групі замовлень доступу не дає: туди додають пакувальників і менеджерів, яким собівартість і прибуток бачити не треба. Перевірка стоїть і в middleware, і в кожній серверній функції, що віддає дані, бо захист тільки на рівні middleware у Next.js уже обходили (CVE-2025-29927).

## Considered Options

- **Cloudflare Access.** Домен уже на Cloudflare, але `*.vercel.app` URL лишається відкритим, поки застосунок сам не перевіряє JWT від Access. Тобто код однаково потрібен, а проксі Cloudflare перед Vercel лише додає ще одну рухому частину.
- **Google OAuth з allowlist email-ів.** Надійно, але це ще один провайдер, а список доступу міняється через деплой.
- **Vercel Deployment Protection.** На Hobby не закриває production-домен.
